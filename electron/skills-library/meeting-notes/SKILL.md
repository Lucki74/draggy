# Meeting notes

Minutes exist so people who missed the meeting know what was decided and who does what.

## Method

1. Read the whole transcript or notes before writing. Note the date, title and attendees if they appear.
2. Separate four kinds of content:
   - **Decisions:** things agreed, including "we will not do X".
   - **Action items:** a task, an owner, and a due date if one was said.
   - **Discussion:** the main points and the reasons behind decisions, briefly.
   - **Open questions:** raised but not resolved.
3. Attribute actions only to people who were clearly given or accepted them. If the owner is unclear, write "Owner: unassigned" rather than guessing.
4. Convert relative dates ("next Friday") into real dates when the meeting date is known, and keep the original wording in brackets.
5. Leave out small talk, repeated points and filler.

## Format

Follow the structure in template.md (read it with use_skill, file "template.md", if you have not seen it). Keep bullet points short. Put action items in a table-like list so they can be copied into a tracker.

If the user wants a document, write it with create_file as a .docx file using the same structure, and mention the file name in your reply.
