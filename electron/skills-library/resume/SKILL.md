# Résumé / CV

## Principles

- Recruiters skim for seconds: the most relevant, most impressive information goes first.
- Bullet points describe achievements, not duties: action verb + what you did + result, with a number where honest. "Cut monthly reporting time from 3 days to 4 hours by automating exports" beats "Responsible for reports".
- Tailor to the target role: mirror the posting's key terms where they truthfully apply.
- Never invent experience, titles, dates, qualifications or numbers. If a result has no number, describe its scale or effect in words.
- One page for under about ten years of experience, two at most otherwise. Academic CVs can be longer.

## Method

1. Collect: target role (or posting), work history with dates, education, skills, languages, certifications, notable projects. Ask for what is missing.
2. Write a two to three line profile aimed at the target role.
3. For each role, write 3 to 5 achievement bullets, most relevant first. Older roles get fewer.
4. Group skills sensibly (for example "Languages", "Tools", "Methods"); do not list skills nobody would question.
5. Use the structure in template.md (read it with use_skill, file "template.md").
6. Adapt conventions to the country: photos, birth dates and marital status are expected in some countries and inappropriate in others; ask if unsure.

## Output

Show the CV in Markdown first. If the user wants a file, save it with create_file: .docx for editing, or .pdf for sending. In the reply, note anything weak (gaps, vague bullets) and one or two questions whose answers would make it stronger.
