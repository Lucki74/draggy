# Objection handling

## Goal

Help the user respond to a buyer's pushback in a way that keeps trust and moves toward the truth. A good reply acknowledges the point, asks one question, and never pressures.

## When to use

- The buyer said something like too expensive, not now, we use a competitor, or I need to ask my boss.
- The user wants to rehearse replies before a call.
- A deal that has gone silent is a case for `use_skill` with `follow-up-sequence`.
- The user wants a general training deck on objections, which is outside this skill.

## Steps

1. Get the exact words the buyer used and the context: stage of the deal, who said it, and what came just before. Use `ask_user` if the user gave only a label.
2. Classify the objection: price, timing, authority, need, trust, or competitor. Say which one it looks like and why.
3. Write a one-line acknowledgement that restates the concern without agreeing to it or arguing with it.
4. Write one question that tests the real reason, for example what the comparison is, what would need to be true, or who else weighs in.
5. Draft two short replies: one for each likely answer to that question.
6. Name what the user should not say, such as a discount, a deadline, or a claim they cannot back.
7. If the user gave facts to support a reply (results, references), use only those. Ask for more instead of inventing.
8. Check tone: would the user say this out loud to a buyer they respect?
9. Offer a practice round: play the buyer and give the user one harder follow-up objection.
10. Note the pattern if the same objection came up before, since it may point to a gap earlier in the sales process.

## Gotchas

- Answering the stated objection when it hides another. "Too expensive" is often "I cannot show value to my boss".
- Offering a discount first. It teaches the buyer that the price was soft.
- A rebuttal that begins with "I understand, but". The word but cancels the first half.
- Handling timing as a scheduling problem. Ask what changes then.
- Pushing past a clear no. Know when the best reply is to leave the door open and stop.
- Reciting a case study the user did not supply. Ask for a real one or leave it out.
- Treating all buyers alike. A procurement lead and an end user object for different reasons.

## Output

The likely real concern, the acknowledgement line, the probing question, two branch replies, and a short do-not-say list. Keep the whole answer under a page.
- Keep replies speakable: one to three sentences each.
- Mark which reply to use if the buyer stays silent after the question.
