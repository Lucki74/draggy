Каждый вызов инструмента проходит одну проверку перед запуском, и это относится и к встроенным инструментам, и к инструментам расширений.

| Режим | Чтение | Правки | Удаление | Команды |
| --- | --- | --- | --- | --- |
| Plan only | Да | Нет | Нет | Нет |
| Ask first | Да | Спрашивает | Спрашивает | Только чтение выполняются, остальные спрашивают |
| Accept edits | Да | Да | Спрашивает | Только чтение выполняются, остальные спрашивают |
| Турбо | Да | Да, в проекте | Да, в проекте | В изолированной среде |
| [YOLO](doc:glossary#auto) | Да | Да | Да | Да |

![Открытое меню режимов разрешений в проекте: Plan only, Ask first, Accept edits, Турбо и YOLO, выбран Accept edits.](shot:app-permission-modes)

> [!WARNING]
> **YOLO** работает без изоляции и действует на всём компьютере. Держите его для машин, которые можно восстановить.

**Accept edits** — режим по умолчанию. Каждая правка показывается как diff и может быть отменена. Chat, у которого нет папки проекта, работает без запросов. В Code параметр `Settings → Code → Preferences → New projects start in` задаёт режим, с которого начинается новый проект.

Панель браузера спрашивает, прежде чем агент начнёт действовать на сайте: **Allow once** или **Allow for this session**.

## Изолированная среда {#sandbox}

В Windows команды запускаются в изолированной среде. В режимах **Ask first** и **Accept edits** папка проекта доступна им только для чтения, а сети у них нет. В режиме **Турбо** они могут писать в папку проекта и пользоваться сетью. Всё за пределами папки проекта требует вашего согласия, и модель должна его спросить. В **YOLO** изоляции нет, он действует на всём компьютере. При включении он просит подтверждение, а команда может запросить права администратора, и тогда появится запрос Windows.

Инструменты Node, такие как npm, npx и vitest, не работают в изолированной среде. Когда модель запускает один из них, Draggy спрашивает один раз, и после вашего согласия он запускается вне изолированной среды. Для настройки изолированной среды в первый раз могут понадобиться права администратора. Windows запрашивает их один раз на компьютер, а не при каждом запуске.

## Чтение не спрашивает

В любом режиме, включая режим планирования, не спрашивается чтение и просмотр файлов, поиск по ним, git status и diff, веб-поиск, ваша библиотека документов, загрузка навыка и запись плана.

## Карточка запроса

![Проект в режиме Accept edits: карточка просит одобрить запуск npm test, ниже кнопки для ответа.](shot:app-settings-code)

| Кнопка | Что охватывает |
| --- | --- |
| Allow once | Этот вызов. Следующий снова спросит. |
| Allow for this task | Этот вид вызовов до конца ответа. |
| Always allow here | Запоминается для этого проекта. Для команды действует на префикс, поэтому разрешение для `npm run` охватывает все скрипты. |
| Don't | Отказ. Модель продолжает работу без него. |

`Settings → Code → Projects` показывает всё, что вы разрешили, с кнопкой **Remove** у каждого пункта.

В `Settings → Code → Permissions` хранятся правила, которые действуют в любом режиме. Выберите **Всегда разрешать** или **Никогда не разрешать**, тип (команда, путь, инструмент или сайт), само правило и где оно действует: во всех проектах или в одном. Правило «Никогда не разрешать» сильнее любого режима и любого «Всегда разрешать», поэтому заблокированная команда остаётся заблокированной даже в auto.
