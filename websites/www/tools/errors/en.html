What it means

A model can only look at a picture if it has a second file beside it, called an image projector. Draggy downloads that file with the model when the repository has one, and starts the model with it. When the engine cannot load the projector, Draggy starts the model without it so text chat keeps working. From then on the model cannot take images, and sending one is refused with this message.

Why the projector may not load

The engine understands a fixed set of projector types. A projector of a type it does not know is refused. A few models ship one that only a modified build of llama.cpp can read, and say so on their own page. Draggy runs the standard llama.cpp release, so those models can be used for text but not for images.

What to do

  • Send the message again without the image. The model still works for text.
  • Choose a different vision model from the model list in Settings → Models.
  • Restarting Draggy, or downloading the model again, makes Draggy try the projector once more. That is worth doing after Draggy has been updated.

What it means

Every model has a context window: the amount of text it can hold at once. Your messages, its replies, tool results and attached files all count. This request is larger than the window the engine was started with, so the engine refused it.

What to do

  • Start a new chat. The old one stays in your history.
  • Lower the compaction limit in Settings → Models so Draggy folds up older messages sooner.
  • Raise the Context window in the same place. A larger window needs more memory, so a model that fits comfortably may stop fitting; see not enough memory if that happens.
  • Attach less at once. A long file or a large paste can fill a small window by itself.

What it means

A model uses a tool by writing a structured call: the tool's name and its arguments. The engine checks every call in the conversation before it answers, and when one is malformed, for example a call with no type or with arguments it cannot parse, it refuses the whole request rather than guess.

The bad call may be one the model has just written, or one that is already in the history of the chat, in which case sending again fails the same way.

What to do

  • Send the message again. A one-off slip usually does not repeat.
  • Start a new chat if it keeps failing. That removes the malformed call from the history.
  • Use a larger model, or switch some tools off. A small model with many tools on may not call them reliably.

What to do

What it means

Draggy talks to its engine on port 11435 of your own computer. Another program is holding that port, so the engine cannot start. It is often a second copy of Draggy, or an engine left running after a crash.

What to do

  • Close any other copy of Draggy, quit Draggy fully, and open it again.
  • On Windows, netstat -ano | findstr :11435 shows which process holds the port. On macOS and Linux, lsof -i :11435 does.
  • Restarting the computer clears anything left over.
